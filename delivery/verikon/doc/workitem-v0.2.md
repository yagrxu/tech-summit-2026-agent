## 1. 客户问题与本期范围

### 已确认的问题、业务后果和证据

| 问题 | 业务后果 | 证据来源 |
|---|---|---|
| 费率按**整份预算包**一次性议定，不按单项 | 一次 SOA 修正即触发**全部中心**重算，而非仅受影响中心 | 业务访谈（MSL）确认为主因 |
| 中心↔访视↔程序的映射只存在于 Excel 与邮件附件 | 无法反查"哪些中心包含被修改的程序"，只能手工翻查 | 业务访谈确认为数据问题 |
| 审批链在邮件与共享盘，无系统留痕 | 事后无人能一次性说清"这条费率是谁批的" | 业务访谈 |
| 金额未标付款方 | Central Lab（申办方直付）与 Local Lab（中心结算）混淆，**发生过重复计费** | 业务访谈；客户内部核算（金额见附录，NDA 后并入） |
| 无法自证"某中心不受影响" | 怕漏担责任，采取**保守全签**（§8 明确此为流程保守做法，非规则要求） | 业务访谈 |

**量化基线**：现状代价已由客户内部核算得出（来源标注为"客户内部核算"），
含重算人工、重复计费多付金额、重签时间成本与项目启动延误。**具体数字待 NDA 后并入附录**。

### 成功指标、基线和验证方式

| 指标 | 基线 | 验证方式 |
|---|---|---|
| **任一费率 / 任一次审批可一键溯源**（第一验收项） | 现状：需翻邮件，无法一次说清 | 任取一行金额，系统返回 SOA 格子 → 费率 ID → 费率版本 → 审批人与时间 |
| 修正案重算范围 = 受影响中心 | 现状：全部中心 | 给定被修改程序清单，输出受影响中心与格子；对未受影响中心输出**明确的"无需重签"结论** |
| 漏项零静默 | 现状：手工复核发现 | 费率缺失的格子进入 `unpriced` 且不计入总额 |
| 口径一致性 | 现状：总额对不上须人工排查 | 预算表显式打印管理费基数口径；每金额带含税标记 |
| 授权与实付双数 | 现状：两数混用 | 同时输出授权总额与预计实付 |

> **第一验收项采用客户原话**：「任何一条费率、任何一次『谁批的』，我能在系统里一键点出来、不用再翻邮件
> —— 这条不成立，前面做得再快我都不敢在评审上认。」本条不成立则其余指标不计。

## 2. 当前海外原型

| 步骤 | 输入 | 处理方式 | 输出 | 责任方 |
|---|---|---|---|---|
| 1 SOA 结构化提取 | Protocol/SOA（合成） | **模型**（仅结构提取） | 访视 × 程序矩阵 + 脚注条件项 | AWS SA |
| 2 周期展开 | 压缩列（`C1–6 D1/8/15`） | **确定性代码** | 访视实例清单 | AWS SA |
| 3 次数与发生率 | 采样点数、脚注条件 | **确定性代码 + 人工假设** | 每格次数、发生率（含署名） | 临床运营（假设）|
| 4 程序名映射 | 方案层英文名 | **确定性代码 + 人工校准** | 公司标准名 → 医院收费项名 | 临床运营 |
| 5 费率匹配 | 中心 × 项目 + 版本 | **确定性代码** | 单价 + 费率版本 + 出处 | AWS SA |
| 6 六层叠加与管理费 | 分层明细 | **确定性代码** | 授权总额 / 预计实付 / 基数声明 | AWS SA |
| 7 输出生成 | 计算结果 | **确定性代码** | 三 Sheet Excel + CSV + CTA DOCX | AWS SA |
| 8 Amendment 影响面 | 基准版 vs 新版 | **确定性代码** | 受影响中心与格子 / 无需重签结论 | AWS SA |
| 9 例外处理 | 漏项、超阈值、超 FMV | **人工** | 第二复核人确认 | 临床运营 + 合规 |

- **部署区域与非生产隔离**：`ap-southeast-1` 独立账号内独立资源命名空间；与任何生产系统无网络或身份连通。
- **完全合成数据来源**：`Project-SOAR-完全合成样例-v1.json`（`synthetic: true`，文件自带声明）。
- **数据、日志和备份边界**：仅合成数据入库；键值存储条目带 TTL；日志不含业务金额明细之外的任何个人信息；无跨账号复制。
- **生产连接禁止项**：不连生产库、不接受生产数据同步、不使用任何客户长期凭证、不在客户账号内创建资源、不接受"配置同生产"的预发环境访问。
- **已知限制**：① 模型仅做结构提取，不参与任何金额计算；② 合成样例仅 1 家中心 2 类访视，未覆盖多队列（Part A/B）多 SOA；③ 费率表缺项按 `unpriced` 列出而非补全；④ 税率不内置；⑤ CTA 模板为示例模板，非客户真实模板。

## 3. 目标 AWS 中国区架构

- **目标架构与数据流**：`前端（Partner）→ API 网关（HTTPS + Bearer/服务身份）→ 函数计算（确定性计算引擎）→ 键值存储（费率版本链 / 预算版本链 / 审批留痕）`；结构化提取调用托管模型服务。数据流单向：Protocol/SOA 与费率表入 → 预算与 CTA 出；**金额计算全程在确定性代码内，不经模型**。
- **责任划分**

| 方 | 责任 |
|---|---|
| 维立康（客户） | 业务口径与范围拍板；假设参数与署名；费率表与映射表内容；合规与税务结论；生产准入与上线决策；密钥自管 |
| 星桥数科（Partner） | 前端与流程编排；生产集成；按契约取数（**不得复制金额规则**） |
| AWS 技术团队 | 确定性计算引擎、API 契约、迁移矩阵、验收证据 |
| 客户生产团队 | 变更流程、审批工具、值班与告警接入 |

- **数据、日志、备份、密钥和审计边界**：数据与日志在中国区内生成与保存，**不出境**；密钥由客户自管，AWS 侧身份不在密钥策略内；写权限收敛至明确的 1~2 人；全部 API 调用与数据访问留审计且使用者不可删除；费率表版本**不可原地修改**（§9）。
- **生产准入、风险接受和上线决策人**：准入由客户 IT 与安全按既有流程判定；风险接受由业务方与合规共同签署；**上线决策人为客户方**，AWS 不承诺上线日期。

## 4. 原型到中国区迁移矩阵

| 原型服务/能力 | 中国区目标或替代 | Endpoint/ARN/IAM/模型差异 | 数据与日志处理 | 步骤/依赖 | 风险/回滚 | Owner | 验证方法 |
|---|---|---|---|---|---|---|---|
| API 网关（HTTP API） | 同类托管 API 服务 | Endpoint 域名后缀不同；ARN 分区由 `aws` 变为 `aws-cn`；需 ICP 备案方可绑自有域名 | 访问日志留中国区 | 建账号 → 建 API → 绑鉴权 | 低；回滚＝保留海外原型不下线 | AWS SA + 客户 IT | 公网 HTTPS 探测 + 证书链检查 + 401 拒绝用例 |
| 函数计算 | 同类托管函数服务 | 分区 ARN 变更；执行角色需重建；运行时版本需确认可用 | 运行日志留中国区 | 打包上传 → 配置环境变量 → 绑 API | 低；回滚＝指回上一版本别名 | AWS SA | 逐接口回归（本件 §8 的 10 项） |
| 键值存储 | 同类托管键值服务 | 表 ARN 分区变更；按需计费模式一致 | 表与备份留中国区；TTL 同配置 | 建表 → 开 TTL → 导入费率表与映射表 | 中（数据迁移）；回滚＝保留原表只读 | AWS SA + 客户 IT | 费率版本链完整性校验 + 历史预算复现比对 |
| 结构化提取模型 | **中国区可用的托管模型服务，模型与版本以中国区实际供给为准** | **模型 ID 与版本不同，提示词与抽取 Schema 需按该模型重新校准** | 仅传合成或脱敏后的 SOA 文本；不传金额与中心标识 | 选型 → 重跑评测集 → 达标后切换 | **中：抽取质量可能变化**；回滚＝人工录入 SOA 结构 | AWS SA + 客户合规 | 同一评测集重跑，字段级准确率与 P95 对比 |
| 确定性计算引擎 | **无差异**（纯代码，无区域依赖） | 无 | 无 | 随函数一同部署 | 无 | AWS SA | 同一输入比对 `calc_id` 与逐行金额 |
| 文档生成（Excel/DOCX） | **无差异**（纯库，无区域依赖） | 无 | 输出文件留中国区 | 随函数一同部署 | 低 | AWS SA | 三 Sheet 结构与汇总页一致性校验 |
| CTA 模板与条款库 | 客户中国区模板库 | 不适用 | 模板留中国区 | 客户提供中国区模板版本 | **中：模板差异导致回填偏差**；回滚＝人工回填 | 客户 Legal + SA | 回填报告：已填字段 / 未匹配占位符 / 金额一致性 |

**本节不可回避的成本（诚实声明）**：迁移后 **① 结构化提取模型需按中国区可用模型重新校准提示词与抽取 Schema；
② CTA 模板与条款库属本地化内容，需按中国区模板版本重新校验回填结果。** 这两项工作量**无法通过架构设计消除**，
必须计入迁移工期。确定性计算引擎与文档生成无区域依赖，是迁移中成本最低的部分。

本期不要求实际部署中国区，也不要求服务 allowlist、账户截图、Region/IP 证明或 IaC 扫描。

## 5. API 与 Partner 契约

| 项目 | 约定 |
|---|---|
| API 版本与基础路径 | `v1`；基础路径为提交的 `base_url`，资源路径 `/budget`、`/budget/excel`、`/amendment`、`/metrics`、`/health`；破坏性变更升 `v2` |
| 请求/响应 Schema | 请求 `{payload, params}`：`payload` 为 SOAR 结构（`site`/`study`/`visits[]`/`rates[]`），`params` 为假设与口径（`overhead_base_layers`、`overhead_rate`、`conditional_rates{rate,source}`、`tax_included`、`tax_rate`、`expected_completion_rate`、`holdback_rate`、`assumption_owner`）。响应含 `lines[]`（每行带 `soa_cell`/`rate_id`/`rate_version`/`payer`/`tax_included`/`assumption_source`）、`layer_subtotals`、`overhead_base_label`、`authorized_total`、`expected_actual_total`、`unpriced[]`、`assumptions[]`、`warnings[]`、`calc_id` |
| 错误结构与状态码 | `{"error": <类型>, "detail": <简述>}`；`200` 成功／`400` 请求体不合法／`401` 无或错 Bearer／`404` 路由不存在（返回可用路由）／`500` 服务端错误。金额相关错误绝不以 `200` + 静默零值返回 |
| 鉴权与服务身份 | 全部接口（含 `/metrics`，运行数据同属业务数据）强制 `Authorization: Bearer <token>`；生产改用 Partner 服务身份 + 短期凭证，**禁止共享长期凭证** |
| 幂等、超时和重试 | `/budget`、`/amendment` 为纯函数式计算，**同输入同 `calc_id`**，天然幂等，可安全重试；建议客户端超时 60s；重试用指数退避；写入侧计数为原子累加 |
| 契约测试 | 以合成样例为固定用例集：① 周期展开实例数 ② 授权/实付双值 ③ 管理费基数声明文本 ④ `unpriced` 计数 ⑤ 假设署名非空 ⑥ 逐行 `rate_version` 非空 ⑦ Amendment 正向命中 ⑧ Amendment 反向"无需重签" ⑨ 无 token 401 ⑩ 错 token 401。Partner 与 AWS 各自在 CI 中跑同一套 |
| 兼容、回滚和弃用 | 只增字段不改语义；`calc_id` 为计算指纹，历史结果永久可复现；弃用需一个版本周期的重叠期；回滚＝函数版本别名指回上一版 |

**前端约束（写入契约）**：前端**不得复制金额规则**（六层叠加、管理费基数、发生率、税费一律由后端计算）、
**不得显示无法追溯的本地金额**（任何展示金额须携带 `soa_cell`/`rate_id`/`rate_version`）、
**不得直连数据库**、**不得使用共享长期凭证**。

### 模型候选

### 推理形态与月度 TCO

> **以下单价为公开标价（AWS 官网定价页），仅用于数量级计算；实际商务价由 BD 与采购出具。
> 公开标价高于实际商务价，故下列数字为上限，不是估计值。**

工作负载假设（需业务方确认）：年 35 个在研项目 × 45 家中心；每项目 1 次初始 + 3 次 Amendment
→ **抽取调用 ≈ 140 次/年**（抽取按 Protocol 计，**不按中心计**）；
**预算构建 ≈ 35 × 45 × 4 = 6,300 次/年 ≈ 525 次/月**，每次 ~1 s / 512 MB。

| 推理形态 | 模型与配置 | 工作负载 | 利用率 | 固定/闲置 | HA/扩缩容/运维 | 月度 TCO | 结论 |
|---|---|---|---:|---:|---:|---:|---|
| **托管推理（Bedrock）** | Haiku 4.5，按 token 计费 | 约 12 次抽取/月，每次 ~20K 输入 + 4K 输出 | 按需，无闲置 | **0** | 托管，无需运维；自动扩缩 | **≈ $0.5（推理）+ 约 $1~3（函数/存储/网关，多为最小计费量）≈ $2~4** | **采用** |
| 自建 GPU（只做分析） | 单卡实例常驻 | 同上 | **≈ 0.05%**（12 次/月 × 数秒） | **≈ $730/月常驻** | 需自建 HA、扩缩容、补丁与值班 | **≈ $730+** | **不采用** |

**结论**：本场景推理调用量极低（抽取按 Protocol 而非按中心计），**推理不是成本中心**；
自建 GPU 的利用率约 0.05%，固定成本高出两个数量级且额外引入运维与值班。

**单位成本口径**：按上表，**每次预算构建的平摊成本 < $0.01**（含推理、计算、存储与网关）。
该数字的分母（项目数 × 中心数 × 版本数）来自业务方需确认的工作负载假设；
分子仅依赖公开标价。**工作负载假设若变化，只影响该单位成本，不影响"托管推理优于自建"的结论** ——
因为自建的固定成本与调用量无关。

- **模型只负责结构化提取**：把 SOA（含跨页表头、合并单元格、混用的勾选符号、脚注编号）转成结构化的访视 × 程序矩阵与脚注条件项清单。**模型不接触任何金额。**
- **确定性代码负责周期展开、费率匹配、发生率应用、六层叠加、管理费基数、税费标记与合计**：同输入必得同输出（同 `calc_id`），可逐行复现，满足 §9 审计要求。**这是把模型排除在金额之外的核心理由 —— 金额必须可复现，模型输出不保证逐字可复现。**
- **人工例外处理与触发条件**：① 费率缺项（`unpriced` 非空）→ 第二复核人；② 条件性程序缺发生率或缺署名 → 临床运营补录；③ 管理费基数纳入第 3/4/5 层 → 需机构书面确认；④ 超阈值总额 → Finance/Procurement；⑤ 超 FMV 偏离 → 合规（否决权）；⑥ 模型抽取置信度低或结构不完整 → 人工录入 SOA 结构。

## 7. 安全、事件与恢复

- **身份、最小权限和审计**：函数执行角色仅具本表读写、日志写入与单一模型调用权限（资源级限定）；无跨账号信任；密钥由客户自管；写权限收敛至 1~2 人；全部调用留审计且使用者不可删除。
- **发现疑似真实数据时的立即动作**：① **立即停止处理**，不再读取、复制、下载或转贴任何片段；② **不自行删除**疑似数据 —— 删除会破坏取证依据，隔离优先于删除：收敛该前缀权限至安全负责人只读，开启并锁定访问日志；③ 记录事实时间线（何时获得、谁提供、何时发现、看到哪些**字段类别**，不抄录原文、不记录具体值）；④ 原型侧回退至纯合成数据，事件查清前不接触任何标称"已处理"的真实数据。
- **报告与通知路径**：**五分钟内**同时通知客户安全/运维负责人、IT BP 与业务负责人，并走客户既有事件响应流程；AWS 侧同步按内部流程上报安全合规与客户团队。**不压案、不私下处理。** 是否对外披露、是否通知受影响主体、是否触发监管报告义务 —— **由客户法务与管理层决定，AWS 提供事实时间线与时间窗参考，不代作合规决定、不代承担。**
- **恢复前置条件**：① 数据范围已框定（谁访问过、是否外流有日志结论）；② 入口校验已生效（见下）；③ 客户安全负责人书面同意恢复。
- **恢复后新增控制**：① **数据入环境前强制自动校验**（邮箱/手机/证件号/地址/姓名全量扫描 + 抽样人工复核），**无校验报告不予审批**；② 目标桶默认拒绝上传，仅经校验的管道可写；③ "已脱敏"不得以口头声明为凭，须产出可复核的脱敏报告（脱敏字段、抽查结果、执行人署名）；④ 将"发现到隔离"的时长纳入可观测指标 —— 下一次应由系统报警，而非由人偶然发现。
