## 0. 范围与目标

### 0.1 业务出发点（均为星云自有数据）

| 现状指标 | 数值 |
|---|---|
| 增值服务订阅率 | 8% |
| 7 天试用后流失率 | 75% |
| Q2 海外出货量同比 | −10% |
| 在线设备规模 | 2,000 万台（北美 / 欧洲 / 日本） |
| 年出货量 | 500 万台 |

端侧 AI 目前输出的是"检测到移动"这一类**给设备看的信号**，不是**给人看的价值**。用户想知道的是"下午三点有人把包裹放在门口了"，而不是"区域 2 有像素变化"。PoC 要验证的正是这一步转换是否成立、成本是否可控。

### 0.2 PoC 的目标：拿到四个数，不是"上线多模态"

| 目标指标 | 定义 | 测量方式 |
|---|---|---|
| 事件识别准确率 | 标注为真事件的样本中被正确分类的比例 | 打码样本离线回放 + 双人标注比对 |
| 误报率 | 每台设备每天推送的错误事件条数 | 困难样本集（风、光影、宠物、邻居、快递员）专项回放 |
| 端到端时延 | 事件发生 → 用户端可见摘要 | 埋点时间戳差值，P50 / P95 |
| 单台设备月云端推理成本 | 见 §2.1 公式 | 独立 PoC 账号内实测 + 可复算模型 |

### 0.3 明确不在范围内（本次 PoC 一律不做）

| 不做的事 | 原因 | 何时可能再谈 |
|---|---|---|
| 人脸身份识别、建立人脸模板库 | 属生物识别，北美有州级专项立法与集体诉讼风险，欧盟需 DPIA，日本 APPI 需单独告知同意 | 第二阶段单独立项，先出同意与影响评估路径 |
| 音频分析 | 部分地区录音需**双方同意**，比视频更严 | 第二阶段，先出各区同意要求清单 |
| 三区数据汇总到单一区域 | 跨境传输与数据驻留义务 | 不计划改变；只跨区汇总不含内容的统计指标 |
| 接入生产设备实时流 | 2,000 万在线设备，一次误配即大规模错误推送 | 用影子模式替代（§1.7） |
| 使用用户历史录像训练或调优模型 | 家庭内部视频含未成年人，属最敏感个人数据 | 不计划；替代路径见 §3.2 |
| 任何生产环境变更、接管星云现有系统运维 | PoC 不进生产、不收权 | 不适用 |

**关于语义检索的说明**：自由语义检索（"上周有什么不一样"这类模糊提问）**在第一版不默认开启**，但**设计不缺**——向量存储与语义检索的完整设计见 **§1.8**，包括索引结构、混合检索排序、embedding 版本迁移、隐私隔离、成本与启用判据。第一版默认只开启 L1 结构化检索与全文检索（§1.8.2），L2 语义层按 §1.8.7 的判据启用，工程上是开关，不是重构。

### 0.4 第一版收窄到什么

**一个区域 + 1~2 类高价值事件 + 仅视频 + 离线回放与影子模式。**

事件类型建议取"包裹放置"与"陌生人徘徊"两类：这两类是用户愿意付费的场景，且负样本容易构造，便于把误报率测准。

## 1. 架构设计

### 1.1 设计原则（针对李昊天团队的真实约束）

星云研发的核心能力是**嵌入式与后端**，团队没有多模态模型研发积累，而窗口只有三个月。因此架构必须让星云**不需要新增一支多模态团队**就能跑完 PoC：

1. **端侧不动模型，只动策略**：复用现有端侧检测作为**预筛器**，改的是触发条件与抽帧策略，属于嵌入式团队的熟悉领域。
2. **云侧不自训练**：PoC 阶段使用托管多模态模型服务，通过提示工程与少样本示例适配场景，不做预训练、不做微调。
3. **事件驱动、异步处理**：不做常开推理。没有事件就没有成本。
4. **与生产物理隔离**：独立账号、独立环境、独立密钥，不复用任何与生产同步的链路。
5. **可替换**：模型调用走适配层，事件结构用开放格式（详见第 4 章反锁定设计）。

### 1.2 端云分工（谁做什么、在哪里跑、明确不做什么）

| 层 | 归属团队 | 职责 | 明确不做 |
|---|---|---|---|
| 端侧固件 | 星云嵌入式 | 移动/声音触发 → 本地预筛 → 抽取 k 帧 + 短片段 → 组装事件包上传 | 不做多模态理解；不生成人脸模板 |
| 接入层 | 星云后端 | 事件包鉴权、限流、按区域路由、同摄像头同场景去重 | 不做跨区域路由 |
| 云侧推理编排 | AWS SA 协助搭建，星云后端维护 | 队列 → 托管多模态模型（帧序列 + 元数据）→ 结构化事件 JSON | 不做身份识别；不写入生产库 |
| 应用层（PoC 壳） | AWS SA 搭建 | 事件摘要、时间轴回看、通知策略（每天一条"唯一值得看的 8 秒"） | **不改星云生产 App**；PoC 使用独立演示壳 |
| 观测与治理 | 共同 | 四个目标指标埋点；提示词与配置版本化；灰度与一键回滚 | — |

**这张表的用意**：李昊天团队在 PoC 中承担的都是嵌入式与后端工作，没有一项需要多模态研发能力。

### 1.3 数据流（逐步标注区域边界与留存）

| 步骤 | 动作 | 数据落在哪 | 留存 | 谁可访问 |
|---|---|---|---|---|
| 1 | 端侧触发 + 本地预筛命中 | 设备本地 | 不留存 | 设备 |
| 2 | 抽 k 帧 + 短片段，组装事件包 | 设备本地内存 | 上传后即清 | 设备 |
| 3 | 上传至**所属区域**接入层（TLS） | 区域内 | — | 接入层服务角色 |
| 4 | 鉴权、去重、入队 | 区域内 | 队列保留期内 | 服务角色 |
| 5 | 托管多模态模型推理 | **区域内**，不出区 | 不留存输入 | 服务角色 |
| 6 | 结构化事件 JSON 落库 | 区域内，星云自有存储 | 事件 JSON 按约定留存期 | 应用角色（只读）、审计 |
| 7 | 事件片段热存 | 区域内，星云自有桶 | 短期热存，之后冷存或删除 | 写权限 ≤ 2 人 |
| 8 | 指标聚合（**不含内容**）跨区汇总 | 汇总区 | 长期 | 星云与 SA 共同查看 |

**边界原则**：内容（视频、帧、事件正文）**不出区**；跨区流动的只有不含内容的统计指标。

### 1.4 关键设计决策与取舍（含代价，不只讲好处）

| 编号 | 决策 | 为什么 | 代价 / 风险 | 如何量化这个代价 |
|---|---|---|---|---|
| D1 | 端侧预筛，只把命中事件上云 | 成本与隐私同时受益 | 预筛阈值调高会漏检 | 出一条"阈值—漏检率—上云帧占比—成本"曲线，由星云选工作点 |
| D2 | 用托管模型，PoC 不自研不微调 | 三个月窗口 + 团队无多模态经验 | 单位调用成本高于自建推理 | 用 §2.3 三档情景比较；PoC 目的之一就是测出真实调用量 |
| D3 | 只做类别检测，不做人脸身份 | 合规风险相差一个量级（§3.3） | 少一个"认出家人"的卖点 | 用户价值用"事件摘要 + 时间轴"替代，A/B 验证是否影响订阅意愿 |
| D4 | 异步事件驱动，不做常开推理 | 无事件即无成本 | 时延高于常开 | 以 P50/P95 时延为验收指标，目标是"用户感知内"而非"实时" |
| D5 | 独立 PoC 环境，不复用预生产 | 预生产若与生产同步，一次误操作可回灌生产 | 环境准备需要开账号的时间 | 开账号与合成数据开工**并行**，不占用关键路径 |

### 1.5 里程碑（可验证产物；**不构成交付日期承诺**）

| 里程碑 | 完成的标志（可看的产物） | 不达标则 |
|---|---|---|
| M1 链路跑通 | 端到端演示录屏 + 事件 JSON 样例 + 埋点看板 | 停在 M1 复盘，不进 M2 |
| M2 两个数 | 准确率与误报率报告（打码样本离线回放，含困难样本分组） | 停止，不进 M3 |
| M3 成本模型 | 可改假设的 TCO 表 + 单台设备月成本上限方案 + 护栏配置 | 停止，不进上线讨论 |

> 里程碑的顺序与判据是本方案的一部分；**具体日期由星云与 AWS 双方在协议与资源就绪后另行确认**，本文档不承诺日期。

### 1.6 非功能指标与验收口径

| 指标 | 定义 | 测量方法 | PoC 目标区间（**待验证假设**） |
|---|---|---|---|
| 事件识别准确率 | 真事件被正确分类比例 | 离线回放 + 双人标注 | 设定目标区间，由 M2 测出真值 |
| 误报条数 | 每设备每天错误推送条数 | 困难样本专项 | 目标为"低于用户关闭推送的阈值"，该阈值由星云埋点给出 |
| 端到端时延 | 事件发生 → 用户可见 | 埋点时间戳差 | P50 / P95 两档分别设目标 |
| 单台月成本 | §2.1 公式 | 独立账号实测 | 设硬上限，见 §2.5 |
| 可用性 | PoC 环境可用时间 | 健康检查 | PoC 级别，不承诺生产 SLA |

**说明**：目标区间是**假设**，不是承诺。PoC 的意义就在于把假设换成实测值；如果实测值达不到目标，正确结论是"不做"或"改范围"，而不是调整目标去凑。

### 1.7 测试与验证方法

**数据来源（按合规优先级排序）**
1. 公开数据集与自有实验室拍摄的场景片（无真实用户数据，协议前即可开工）；
2. 星云**自有账号内**抽样并打码的事件片段（脱敏脚本由 SA 提供，**由星云自己的人执行**，产出仅为打码后文件与可复核的脱敏报告）；
3. 困难样本集：风吹草动、光影变化、宠物、邻居、快递员、夜间红外，六类各自单列指标。

**影子模式**：PoC 与现有链路并行运行，**不对外推送任何通知**，只产出对比报告。这样既能拿到准确率与误报率两个真实数字，又对 2,000 万在线设备零影响。

**标注与评审**：双人独立标注 + 抽检复核；标注规范随交付物一并移交（见第 4 章）。

**治理机制**（PoC 阶段即具备，不留到上线才做）
- 提示词与配置进版本库，每次变更可追溯"改了什么、谁改的、改前什么样"；
- 灰度发布 + 一键回滚；
- 每次模型调用留可查记录（输入引用、输出、耗时、成本）。

### 1.8 向量存储与语义检索设计

本节回答两个问题：用户"用一句话找出那段视频"这件事在系统里怎么实现，以及这套能力如何做到可分阶段启用、可换供应商、可按户隔离、可被删除验证。

#### 1.8.1 检索链路总览（两层，L2 可开关）

| 层 | 组成 | 回答什么问题 | 第一版 |
|---|---|---|---|
| **L1 结构化层** | 事件 JSON 的字段索引：时间、事件类别、设备 ID、家庭 ID、置信度 | "昨天有人来过吗""包裹什么时候到的" | **默认开启** |
| **L1b 全文层** | 事件摘要文本的倒排索引（BM25） | "快递""陌生人""宠物"这类词命中 | **默认开启** |
| **L2 语义层** | 摘要文本的向量索引 + kNN 检索 | "上周有什么不一样""像上次那样的情况" | **设计就绪，按 §1.8.7 判据启用** |

三层共用同一个查询入口：查询 → 意图解析 → 生成结构化过滤条件（必填）+ 关键词（可选）+ 查询向量（L2 启用时）→ 混合排序 → 返回事件列表。

#### 1.8.2 写入侧：事件如何变成可检索对象

| 步骤 | 产出 | 说明 |
|---|---|---|
| 1 | 多模态模型对帧序列输出**结构化标签 + 一句话摘要** | 一次调用同时产出两者，不额外增加推理成本 |
| 2 | 事件 JSON 写入 JSONL（**真源**） | 含 `event_id` / `home_id` / `region` / `device_id` / `ts` / `category` / `confidence` / `summary` / `clip_ref` |
| 3 | 结构化字段写入 L1 索引 | 常规二级索引 |
| 4 | 摘要文本写入 L1b 倒排索引 | BM25 |
| 5 | **摘要文本 embedding → 向量写入 L2 索引** | 仅 L2 启用时执行；向量记录携带 `embedding_model_version` |

**只对摘要文本做 embedding，不对视频帧做 embedding。** 理由有三：摘要是已经过滤掉个人可识别细节的短文本，隐私面小；文本 embedding 的维度与成本远低于图像 embedding；换模型时重建代价小（见 §1.8.6）。

#### 1.8.3 向量索引结构

| 设计项 | 取值 | 为什么 |
|---|---|---|
| 向量维度 | 1024（文本 embedding 模型输出） | 与所选 embedding 模型一致；维度写入索引元数据 |
| 索引算法 | HNSW，`m = 16`，`ef_construction = 128`，查询 `ef_search = 64` | 事件级数据量下召回与延迟平衡的常规工作点；三个参数均为可调项，M2 用真实提问日志校准 |
| 距离度量 | 余弦相似度 | 文本 embedding 的通用选择；向量入库前归一化 |
| 分片键 | `region` → **一级分片** | 数据不出区（§1.3），区域隔离在索引层就成立 |
| 命名空间 | `home_id` → **每户一个命名空间** | 跨户永不召回；这是隐私要求，不是性能优化 |
| 元数据过滤 | **前置过滤**：先按 `home_id` + 时间范围 + 类别缩小候选集，再做 kNN | 避免全库扫描，延迟与成本同时下降；也让"跨户召回"在物理上不可能发生 |
| 向量体积 | 1024 维 × 4 字节 ≈ 4 KB/事件 | 用于容量与成本估算（§2.4） |

#### 1.8.4 查询侧：混合检索与排序

1. **意图解析**：把用户问句解析为 `{时间范围, 类别集合, 关键词, 自由语义部分}`。固定问句（5~8 个模板）走纯 L1，零向量成本。
2. **候选召回**：L1 过滤得到候选集 → L1b BM25 取 Top-K1 → L2 kNN 取 Top-K2（K1 = K2 = 50 起，按 M2 调）。
3. **融合排序**：**RRF（Reciprocal Rank Fusion）** 合并两路结果，`score = Σ 1/(k + rank)`，`k = 60`。选 RRF 而不是加权分数相加，因为 BM25 分数与余弦相似度不同量纲，权重需要按数据集反复调，RRF 只用排名、更稳。
4. **重排（可选）**：Top-20 交给模型做一次相关性重排，仅在 L2 启用且用户提问明显模糊时触发（成本按需）。
5. **兜底**：语义召回为空时降级为 L1 结果 + 明确提示"按时间/类别列出"，不返回空白页。

#### 1.8.5 真源与派生物（这一条决定退出成本）

- **JSONL 事件流是唯一真源**，落在星云自己的存储桶里。
- **L1 / L1b / L2 三个索引全部是可重建派生物。** 任何一个索引损坏、换实现、换供应商，都可以从 JSONL 全量重建。
- 重建成本是**可算的**，不是未知风险：L1 / L1b 重建只花计算时间；L2 重建 = 一次全量摘要 embedding 的调用费，数字见 §2.4.4。

#### 1.8.6 embedding 版本迁移（换模型不停服）

```
EmbeddingProvider 接口
  embed(texts: list[str]) -> list[vector]
  dim() -> int
  version() -> str        # 写入每条向量记录
```

换 embedding 模型的标准动作：
1. 新模型以新 `version` 双写进**新索引**（旧索引继续服务查询）；
2. 后台从 JSONL 回填历史事件的新向量；
3. 回填完成后按 `home_id` 分批切流到新索引，出问题按批回滚；
4. 观察期结束后下线旧索引。

**任何时候都不存在"索引与模型版本不一致"的混合查询**——查询只打一个索引版本。

#### 1.8.7 L2 的启用判据（不凭感觉上向量）

M1/M2 阶段记录真实提问日志，统计**模板 + 全文两层的覆盖率**：

| 覆盖率 | 决策 |
|---|---|
| ≥ 95% | 不启用 L2；为长尾付全套向量成本与迁移成本不划算 |
| 85% ~ 95% | 先扩模板与同义词表，再评估 |
| < 85% | 启用 L2，按本节设计实施 |

这条判据的意义：**把"要不要上向量"变成一个有数据支撑的决定**，而不是一开始就背上索引与 embedding 的迁移包袱。设计先备好，开关留着。

#### 1.8.8 合规约束（向量也是个人数据派生物）

| 约束 | 做法 |
|---|---|
| 驻留 | 向量索引按 `region` 分片，与事件同区，**不跨境** |
| 留存 | 向量记录继承事件的留存期，事件到期即删向量 |
| 删除可验证 | 删除某户数据时，按 `home_id` 命名空间整体删除，并输出删除前后向量计数对比作为**删除证明** |
| 最小化 | 只 embedding 摘要文本，不 embedding 原始帧；摘要生成时即不写入可识别个人的细节 |
| 访问控制 | 查询强制携带 `home_id`，服务端校验，**不存在无 `home_id` 的全局检索接口** |

### 1.9 工程规范（PoC 代码按生产规范写）

PoC 是验证原型、不是生产系统，但**代码质量不降级**——否则星云团队复现不了，也无法判断结论可信。约定如下：

| 项 | 要求 |
|---|---|
| 代码组织 | 与生产同构的分层；配置外置，不硬编码环境与密钥 |
| 可复现 | 一条命令起环境；依赖锁定版本；随机种子固定 |
| 测试 | 关键路径单元测试 + 一组端到端回归用例（含困难样本） |
| 可观测 | 结构化日志、指标埋点、调用成本埋点，三者齐全 |
| 变更治理 | 提示词与配置进版本库，变更可追溯"改了什么、谁改的、改前什么样"；灰度 + 一键回滚 |
| 交付形态 | 星云自己的仓库，纯文本 / 代码；**不埋在托管控制台配置里** |
| 评审 | 关键设计与代码由星云团队复核，**结论以星云能自行复现为准**，不以口头讲解为准 |

## 2. 成本估算

> 本章不给结论性报价，给的是**张锐可以自己改假设重算的口径**。附录 B 是空白模板。

### 2.1 成本模型公式（自下而上）

```
单台设备月成本
  = 月事件数 n
      × ( 上云帧数 k × 单帧推理单价 p_infer + 单事件元数据处理 p_meta )
  + 事件片段存储量 s × 留存天数 d × 存储单价 p_store
  + 出流量 t × 出流量单价 p_egress
  + 固定平台开销 F / 覆盖设备数 N
```

**全量年成本 = 单台月成本 × 接入设备数 × 12**（PoC 阶段仅按 PoC 设备数计算）。

### 2.2 假设表（每个参数标明"由谁确认"；未定的给临时口径）

| 参数 | 符号 | PoC 初始假设 | 由谁确认 | 状态 |
|---|---|---|---|---|
| 每台每月事件数 | n | 由星云埋点给出 | 周鹏（产品埋点） | **TBD** → 临时口径：取现有端侧告警条数上限，按最坏情况估 |
| 单事件上云帧数 | k | 建议 3~5 帧 | SA + 李昊天 | 假设，M2 调优 |
| 上云帧占总帧比 | x | 目标个位数百分比 | 端侧预筛阈值决定 | 假设，D1 曲线给工作点 |
| 事件片段大小 | s | 由端侧编码参数决定 | 李昊天 | **TBD** → 临时口径：按现有云录像的平均片段大小 |
| 留存天数 | d | 热存短期，之后冷存或删 | 林雪琴 + 张锐 | **TBD** → 临时口径：**按最严处理**，取最短可用留存期 |
| 单帧推理单价 | p_infer | 商务约定 | AWS BD | **不在本文档范围** |
| 存储 / 出流量单价 | p_store / p_egress | 商务约定 | AWS BD | **不在本文档范围** |
| 固定平台开销 | F | PoC 阶段极小 | SA | 假设 |

> **TBD 处理原则**：拿到确认答案之前，一律**按最严 / 最坏情况估算**，不用乐观值撑低成本数字。

### 2.3 三档情景

| 情景 | 假设特征 | 用途 |
|---|---|---|
| 保守 | 事件数取上限、预筛命中率偏高、留存取长 | 给 CFO 做最坏情况预算上限 |
| 基准 | 埋点实测中位数 | 决策用 |
| 激进 | 预筛调紧、抽帧减少、去重命中率高 | 验证优化天花板 |

三档共用同一张表，只换假设列 —— 张锐可以在 Excel 里直接改。

### 2.4 五个成本旋钮（每个都标副作用）

| 旋钮 | 怎么降成本 | 预期影响 | 副作用 |
|---|---|---|---|
| 端侧预筛阈值 | 只有命中才上云，直接压低 x | 影响最大的一个旋钮 | 阈值过紧会漏检，需在 D1 曲线上选点 |
| 事件触发 vs 常开 | 无事件不推理 | 结构性省钱 | 时延高于常开 |
| 抽帧策略 | 单事件抽 k 帧而非整段 | 与 k 线性相关 | k 过小影响判别，M2 调 |
| 冷热分层 + 留存期 | 热存短期，之后冷存或删 | 存储项显著下降 | 回看体验受限，需产品确认 |
| 去重 / 缓存 / 批处理 | 同摄像头同场景不重复推理；低时延容忍场景批处理 | 视重复率而定 | 实现复杂度上升 |

### 2.5 成本护栏（张锐真正要的不是"便宜"，是"不会失控"）

1. **单台设备月成本硬上限**写进设计：超限即**自动降级**——退回只发端侧告警、不上云推理，用户不至于完全没有功能；
2. **预算告警 + 配额**：按设备、按区域分摊可见，不是一张看不懂的总账单；
3. **成本回归测试**：把"单台月成本"作为指标纳入日常检查，异常即告警，不等月底账单；
4. **PoC 在独立账号内**：PoC 自身花费单独可见，与生产账单不混；PoC 结束**到期自动收回**资源；
5. **每个旋钮都有默认安全值**：默认配置是省钱方向，需要显式调整才会更贵。

### 2.6 本章的边界声明

- 本章**不构成报价**，也不构成预算承诺；
- 单价类参数（p_infer / p_store / p_egress）留空，由星云与 AWS 商务填入；
- SA 提供的是**公式、假设表、敏感度顺序与护栏机制**；数字由星云自行填入复算，结论归星云。

### 2.7 敏感度排序（先调哪个旋钮）

按对总成本的影响排序：**上云帧占比 x → 每台事件数 n → 抽帧数 k → 留存天数 d → 出流量 t**。
建议 M3 阶段只测前三项的真实值，后两项用区间即可。

## 4. 退出路径

退出路径不是礼节性章节。下面每一条都写清**谁做、产出什么、多久**，可以直接当验收清单用。

### 4.1 三种退出情景

| 情景 | 触发条件 |
|---|---|
| E1 结论为"不做" | M2 或 M3 指标不达标，PoC 结论是不继续 |
| E2 结论为"做，但自建或换供应商" | PoC 验证成立，星云选择自研或其他方案 |

### 4.2 退出动作清单

| 类别 | 动作 | 谁做 | 产出物 |
|---|---|---|---|
| 数据 | 导出星云在 PoC 环境中的全部数据；随后删除，含备份与日志副本 | 星云执行，SA 配合 | 数据导出清单 + **删除证明** |

| 设计点 | 做法 | 带来的效果 |
|---|---|---|
| 事件结构 | 事件 JSON 用开放结构，字段语义自描述，**不含供应商专有字段** | 换方案时数据不用转换 |

| 基础设施定义 | 环境以代码描述 | 可重建，也可对照着在别处重建 |
